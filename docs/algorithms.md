# Algorithms and evidence

Phase 1 discovers registered image/video extensions case-insensitively. Filename extension selects the handler, not a claimed codec. FFprobe, when installed, identifies streams and actual container/codec information. Unsupported/corrupted metadata does not prevent binary hashing.

Exact comparison groups by file size in SQLite, then computes the complete SHA-256 for size candidates in 1 MiB chunks. Only matching complete digest and size are `EXACT_DUPLICATE`. Unique-size files still receive metadata but do not require a digest. Identity is checked before/after hashing and cleanup rehashes both selected and retained copies. No partial hash proves equality. Results show algorithm, digest, paths, sizes and potential savings.

Retention favors a protected original/asset. Otherwise, if exactly one member lacks “copy”, “duplicate” or a trailing numbered-parentheses marker, it is suggested. Multiple plausible originals means manual selection, with every file initially kept. File size, capture time and filesystem timestamps do not prove originality or image quality. Recommendations only concern equal bytes in Phase 1.

Pillow normalizes EXIF orientation and creates bounded-dimension image previews. HEIF uses pillow-heif. Animated-image metadata includes frame count and animation flag, and browser-compatible animated previews retain animation. RAW thumbnails or half-size rawpy decoding support visual matching and preview; verified RAW/export asset relationships remain later work. FFprobe records duration, dimensions, frame-rate rational, codec, audio/video stream counts, bitrate, container and raw stream details. ExifTool data is retained when installed. Timestamp strings remain as supplied when timezone is ambiguous.

Phase 2 now implements versioned pHash/dHash, BK-tree candidate indexing, complete-link grouping and configurable heuristic thresholds. See [similar-photo algorithms and limits](phase-2.md). Approximate matches remain SIMILAR_CONTENT and require manual review. Phase 3 now adds nine-position video/animation comparison with duration/frame indexes and complete-link grouping; see [implementation and limits](phase-3.md). Phase 4 adds crop-aware/embedding comparison and temporal partial-overlap alignment. The Phase 4 features are not implemented yet. No universal confidence percentage or unsupported accuracy/performance guarantee is displayed.
