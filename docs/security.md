# Local security and cleanup safety

The launch command binds IPv4 loopback only. Host names are restricted to localhost/127.0.0.1. A random per-installation token is saved with mode 0600 where supported. The UI exchanges it through `/session` for an HttpOnly SameSite=Strict cookie. State-changing cookie requests require an allowed Origin; explicit Bearer-token clients may omit Origin. Cross-origin requests are rejected; no permissive CORS headers are enabled. The launch token appears in a fragment, not in request URLs or access logs. Only local users with the token should access this workspace. Windows ACL inheritance governs token-file protection there.

API preview and cleanup accept database IDs, not arbitrary filesystem paths. Previews verify the snapshot identity; videos use range-capable streaming responses. Previewing a corrupted file uses local decoders with their normal limitations, not a media sandbox. Keep dependencies patched. Image decompression-bomb limits remain enabled.

Cleanup has no permanent-delete endpoint. Trash is the default. Quarantine is an explicit same-volume alternative. Errors never cause fallback to deletion. Quarantine folders are always excluded from scanning. RAW originals, potential photo/video companion pairs and user-protected paths cannot be cleaned up. Possible Live Photo pairing is deliberately conservative and is not asserted as true asset pairing.

A dry-run plan requires saved uncheck choices and an intact retained duplicate, lasts ten minutes, and cannot be replayed once execution starts. Hashes are recalculated for selected and retained media before a batch and immediately before each move. Symlinks, changed parent paths, file replacements, changed timestamps and missing keepers block cleanup. Quarantine restore verifies digest and uses a same-volume no-overwrite hard-link operation; filesystems lacking hard links report an error and retain quarantine contents.

The application does not lock out external applications or malicious local filesystem actors. Checks reduce accidental-race risk but do not make multiple file operations atomic. Do not edit/move a collection during cleanup. Quarantine directories and filesystem renames must be trusted; a hostile process racing directory replacements is outside this local-user threat model. Device/inode guarantees vary across mounted filesystems; questionable identity or failed operations should be reviewed and rescanned.

Per-item intent is committed before moving. A crash during OS Trash can leave uncertain status; history reports `interrupted` rather than claiming success. For quarantine, history records both paths and hashes for explicit restore. Never infer disappearance from an unplugged drive, and do not silently resume cleanup after restart. Diagnostics contain events and job IDs; inventory/cleanup history necessarily stores sensitive paths locally. Delete or export those records only with awareness of their contents. No telemetry exporter, analytics or media upload is configured.
