# Phase 1 delivery

Implemented: modular Python 3.12 backend, authenticated local API, React/TypeScript UI, Tailwind styling and themes, TanStack Query state, SQLite WAL with immutable Alembic schema, multi-root streaming discovery, metadata handlers, identity-keyed cache reuse, SHA-256 equality groups, persistent review choices, advisory original-name retention, SSE/polling progress, managed pause/resume/cancel, saved scan history, range video/image previews, safe cleanup plans, explicit confirmation, Trash and same-volume quarantine, recovery history and no-overwrite restore.

Created source areas: `apps/desktop/backend/app/{api,core,scanner,metadata,hashing,grouping,retention,cleanup,database,workers}`, `apps/desktop/backend/migrations`, `apps/desktop/backend/tests`, `apps/desktop/frontend/src/{components,pages,hooks,services,types}`, `.vscode`, `scripts`, `desktop` release notes and `docs`. Root `run.sh` now launches the new backend. Earlier app/static/tests/requirements were moved intact to `legacy/`, preserving prior work. No empty similarity handlers or mock completed APIs are installed.

Validation commands: `scripts/check.sh` (Ruff, pytest, Vitest, TypeScript/Vite); Playwright `scripts/browser-smoke.mjs` against the synthetic `scripts/smoke-server.py`; `uv build apps/desktop/backend` and wheel-content check for migrations; launcher help and shell syntax checks; npm dependency audit. Results: 21 backend pytest tests passed; 3 frontend Vitest/React Testing Library tests passed; Ruff, TypeScript and production build passed; real Chrome smoke workflow passed at desktop/mobile viewport sizes; wheel included both migration files. Frontend dependency installation reported zero vulnerabilities after patching Vitest. One known test-client httpx deprecation warning is described in testing.md.

Safety tradeoff: permanent deletion was intentionally removed from the new workflow. Default cleanup uses Trash; explicitly selected quarantine provides recovery records on the same volume. Ambiguous originals keep all files selected. RAW and potential photo/video pairs remain protected until a later engine can explain their relationship accurately. The possible-pair heuristic is not verified Apple Live Photo recognition.

Known limits: exact equality only in Phase 1; FFprobe/ExifTool are not installed in this workspace, so full video/RAW metadata requires those tools; RAW previews and advanced decoders remain unavailable; video playback depends on browser codecs; animated-image preview is still-image only; root identity is session-local rather than a stable hardware UUID; resume re-enumerates rather than restoring an open directory cursor; no 100k-file performance guarantee; no Windows/Linux release certification; no Tauri shell, signed installer or bundled release runtime yet. Changing database/cache location is currently a launch option, not an in-app migration. Scheduling and threshold settings are deferred with the engines they configure.

Run `./run.sh`, open its printed launch link, then Scanner → Duplicate review → Preview cleanup → explicit confirmation. Development installation instructions for fresh macOS/Linux and Windows are in README. Normal operation is local and offline after dependencies are installed.

Next recommended implementation: **Phase 2**, versioned pHash/dHash plus image normalization and indexed candidate search, calibrated evidence/classifications, side-by-side comparison enhancements and cross-format regression fixtures. Phase 3 will introduce multi-frame video fingerprints; Phase 4 partial/advanced matching; Phase 5 Tauri lifecycle and release packaging. None is represented as already complete.
